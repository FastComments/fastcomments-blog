# [postlink]審核改進已發布[/postlink]

{{#unless isPost}}
審核日誌現在會顯示每個事件影響的對象（人或事）的名稱，且您可以對其進行搜尋。現在還加入了日期範圍、子租戶搜尋、更新時的欄位層級差異，以及相符的 API 篩選條件。
{{/unless}}

{{#isPost}}

### 新功能

審核日誌一直以來都會記錄執行動作的人員以及動作的對象。本次發布的重點是讓這些記錄在不離開頁面的情況下即可閱讀與搜尋。

如果您想了解特定審核員發生了什麼事，首先必須找到他們的 ID；而如果該審核員已被移除，就無法再以 ID 進行查找。事件會說明某項內容被刪除、由誰以及何時刪除，但在某些情況下名稱會缺失。

現在名稱會與 ID 同時在事件發生時被捕獲，即使之後被刪除仍會保留，您也可以對其進行搜尋。

### 受影響欄位

表格中新增了 **Affected** 欄位，顯示事件作用的對象（人或物件）的名稱。對於人員，會顯示類似 `jsmith (jsmith@example.com)`。對於小工具自訂或審核群組，則顯示您為其命名的名稱。對於媒體檔案，則顯示您上傳的檔名。

表格上方有相對應的搜尋框 **Who or what was changed**。輸入名稱、電子郵件地址或 ID，即可找到影響該人或物件的事件。您不必先知道是哪一種，也不必先查找內部 ID。

此版本之前的事件未附帶名稱，但仍保有原本的 ID，因此相同的搜尋框仍可透過 ID 找到它們。

### 日期範圍

篩選列現在有 **Date Range** 下拉選單，提供「最近 30 天」、「最近 90 天」、「去年」、「全部時間」以及 **Custom range**，後者會顯示「起始」與「結束」日期選擇器。

日期範圍是縮小搜尋範圍最簡單的方式，搭配其他篩選條件則是最快找到目標的方法。

### 管理帳戶

如果您的帳戶管理其他租戶，會出現 **Include sub-tenants** 勾選框。勾選後會一次搜尋您的帳戶及其管理的所有租戶，並在 **Tenant** 欄位顯示每筆事件來源的帳戶。

在此之前，每個租戶的日誌只能單獨閱讀，因此要回答「本週是否有人觸及我們的任何資產」時，需要逐一切換至各租戶。

### 更新現在會記錄變更內容

編輯團隊成員時，以前只會記錄最終的權限集合。這只能告訴您目前的權限是什麼，卻無法得知之前的狀態，因此「誰在何時移除此人的計費存取權」無法回答。

更新事件現在會包含一個 `changes` 映射，只列出實際變更的欄位，並提供其先前與新值。未變更的欄位會被省略，因而權限變更只會顯示為一行，而非一長串布林值。

### 描述與變更背後的裝置

破壞性事件現在會附上一句簡單的描述文字，例如「Removed user from the account.」頁面檢視事件有描述，而刪除事件卻沒有，這是相反的情況。

會變更內容的事件也會記錄執行變更的瀏覽器。會話以雜湊方式記錄，讓同一人的行為可被關聯，同時不會在日誌中存儲任何可被重放的資訊。

### 其他改進

- 修正了分頁與篩選組合的部分問題。
- 登入事件的 **Who** 欄位顯示空白。實際上使用者名稱一直存在於記錄中，只是頁面未讀取到。
- 動作欄位將登入事件顯示為 N/A，因為 Login 不在動作名稱清單中。
- 審核日誌頁面無法顯示 SSO 使用者的名稱，會顯示「Missing User」。現在已正確解析。
- 在具有長時間歷史的帳戶上，頁面載入速度大幅提升。

### API 相關

`/api/v1/audit-logs` 端點新增了相符的篩選條件：`username`、`ip`、`crudType`、`resourceName`、`targetId`、`target`（用於子字串搜尋），以及 `includeManagedTenants`。回應現在會包含 `targetId`、`targetLabel` 與 `ua`。

若您已經呼叫此端點，需注意兩項變更。`before` 現在可單獨使用，先前若未同時傳遞 `after` 則會被忽略。`limit` 現在上限為 10,000，預設為 5,000；之前則沒有上限。
