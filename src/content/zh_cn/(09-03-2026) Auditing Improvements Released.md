# [postlink]审计改进已发布[/postlink]

{{#unless isPost}}
审计日志现在显示每个事件影响的对象或人员的名称，并且您可以对其进行搜索。现在还支持日期范围、子租户搜索、更新时的字段级差异以及匹配的 API 过滤器。
{{/unless}}

{{#isPost}}

### 新功能

审计日志一直记录执行操作的人员以及操作的对象。本次发布旨在让这些记录在不离开页面的情况下即可阅读和搜索。

如果您想了解特定版主发生了什么，首先必须找到他们的 ID；如果该版主已经被删除，就没有任何方式可以根据 ID 进行查找。事件会说明某些内容被删除、由谁以及何时删除，但在某些情况下名称缺失。

现在，名称会在事件发生时与 ID 一起捕获，因此即使被删除也会保留下来，您可以对其进行搜索。

### 受影响列

表格中新增了 **Affected**（受影响）列，显示事件作用的人员或对象的名称。对于人员，它显示类似 `jsmith (jsmith@example.com)`。对于小部件自定义或审核组，则显示您为其命名的名称。对于媒体文件，则显示您上传的文件名。

表格上方有一个对应的搜索框 **Who or what was changed**（谁或什么被更改）。输入名称、电子邮件地址或 ID，即可查找影响该人员或对象的事件。您无需事先知道是哪三者中的哪一个，也无需先查找内部 ID。

在此版本发布之前创建的事件没有附带名称，但仍保留了它们一直拥有的 ID，因此相同的搜索框仍可通过 ID 找到它们。

### 日期范围

过滤行现在提供 **Date Range**（日期范围）下拉菜单，包含最近 30 天、最近 90 天、去年、全部时间以及 **Custom range**（自定义范围），后者会显示“从”和“至”日期选择器。

日期范围是缩小搜索范围的最简便方式，将其与其他过滤器组合使用是最快找到目标的方法。

### 托管账户

如果您的账户管理其他租户，则会出现 **Include sub-tenants**（包含子租户）复选框。勾选后，搜索会一次性在您的账户及其管理的所有租户中进行，并在 **Tenant**（租户）列中显示每个事件来源的账户。

此前只能单独读取每个租户的日志，因此要回答“本周是否有人触及我们的任何资产”时，需要逐个切换租户进行查看。

### 更新现在记录更改内容

编辑团队成员时过去只记录最终的权限集合。这只能告诉您当前的权限，而无法说明之前的权限，因此“谁在何时移除了此人的计费访问权限”无法回答。

更新事件现在包含一个 `changes` 映射，仅列出实际更改的字段，并提供其之前和新的值。未更改的字段会被省略，因此权限更改只会显示为一行，而不是一堆布尔值。

### 描述以及更改背后的设备

破坏性事件现在附带一条简短的描述性句子，例如 “Removed user from the account.”（已将用户从账户中移除）。页面浏览事件有描述，而删除事件没有，这在之前是相反的。

进行更改的事件还会记录发起更改的浏览器。会话信息以哈希形式记录，以便在不在日志中存储可重放信息的前提下关联同一人的操作。

### 其他改进

- 一些分页和过滤组合的修复。
- 登录事件的 **Who** 列显示为空白。用户名一直在记录中，只是页面未读取到。
- 动作列将登录事件渲染为 N/A，因为登录未出现在动作名称列表中。
- 审计日志页面无法显示 SSO 用户，显示为 “Missing User”。现在已正确解析。
- 在拥有长历史记录的账户上，页面加载速度显著提升。

### 对 API 的影响

`/api/v1/audit-logs` 接口新增了匹配过滤器：`username`、`ip`、`crudType`、`resourceName`、`targetId`、`target`（用于子字符串搜索）以及 `includeManagedTenants`。响应现在包含 `targetId`、`targetLabel` 和 `ua`。

如果您已经调用此接口，有两点值得注意。`before` 现在可以单独使用，而之前只有在同时传递 `after` 时才会生效。`limit` 现在上限为 10k，之前没有上限。默认值仍为 1k。
